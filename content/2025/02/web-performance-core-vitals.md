# Web Performance in 2025: A Practical Guide to Core Web Vitals

Page speed isn't a nice-to-have anymore. Google uses Core Web Vitals as a ranking signal, and users expect pages to load in under two seconds. If your site is slow, you're losing both traffic and revenue.

Here's what actually matters and how to fix it.

## The Three Metrics That Matter

Google's Core Web Vitals have stabilized around three metrics:

### LCP — Largest Contentful Paint
**What it measures:** How long until the largest visible element (usually a hero image or heading) renders.

**Target:** Under 2.5 seconds.

**Common fixes:**
- Serve images in WebP/AVIF format
- Use `fetchpriority="high"` on hero images
- Preload critical fonts with `<link rel="preload">`
- Eliminate render-blocking JavaScript

### INP — Interaction to Next Paint
**What it measures:** The responsiveness of your page when users interact with it (click, tap, keyboard).

**Target:** Under 200 milliseconds.

**Common fixes:**
- Break up long JavaScript tasks with `requestIdleCallback`
- Defer non-critical third-party scripts
- Use `content-visibility: auto` for offscreen content
- Minimize main thread work

### CLS — Cumulative Layout Shift
**What it measures:** Visual stability. How much the layout shifts while loading.

**Target:** Under 0.1.

**Common fixes:**
- Always set `width` and `height` on images and videos
- Reserve space for ads and embeds
- Use `font-display: swap` with size-adjusted fallback fonts
- Avoid dynamically injected content above the fold

## Measuring Performance

Don't optimize blind. Use these tools:

1. **PageSpeed Insights** — Google's own tool, uses real-world data
2. **Lighthouse** — Built into Chrome DevTools for lab testing
3. **Web Vitals Extension** — Real-time CWV overlay while browsing
4. **CrUX Dashboard** — 28-day rolling averages from real Chrome users

The key insight: **lab data tells you what's possible, field data tells you what's real.** Always check both.

## Quick Wins Checklist

If you want to improve your scores today, start here:

```
□ Enable text compression (gzip/brotli)
□ Set proper cache headers (1 year for hashed assets)
□ Lazy-load images below the fold
□ Self-host fonts instead of using Google Fonts CDN
□ Remove unused CSS and JavaScript
□ Use a CDN for static assets
□ Add explicit dimensions to all media elements
□ Defer analytics and tracking scripts
```

Performance improvements have measurable business impact:

## Architecture Decisions That Scale

For long-term performance, consider these architectural patterns:

- **Static Site Generation** for content-heavy sites (Pelican, Next.js, Astro)
- **Edge computing** for personalized content without round-trip latency
- **Image CDNs** like Cloudinary or imgix for automatic format negotiation
- **Progressive enhancement** over client-side rendering for content sites

> Performance is not a sprint—it's a culture. The best teams measure continuously, set budgets, and treat regressions like bugs.
